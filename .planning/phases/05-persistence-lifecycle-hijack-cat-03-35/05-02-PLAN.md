<objective>
Build the false-positive gate before the patterns, not after. Every specimen here exists because a
real document says something a CAT-03 pattern could plausibly match, and every one is in the tree
before the pattern that might fire on it.

Purpose: this repo's own recorded lesson is that green tests immediately after a widening are its
weakest evidence, and twice a pattern reached review with a control the corpus was not actually
holding. Two of this phase's locked decisions depend on a specimen existing: D-03's AMENDMENT
withdrew "independent of what the command does" because a binding-only rule fires on essentially
every real hooks config, and D-04 can only drop `PI070`'s addressee requirement because the repo's
own documentation and its agent-facing workflows are the gate. Both of those are measurements made
on one machine until they are measurements made by `corpus_test`.

Output: six prose specimens and three agent-hooks-configuration specimens, each with its
`Decision it defends` row; two mutation proofs showing that the withdrawn literal reading of D-03
and a cue-less reading of D-04 both fail against these specimens; and the two-sided documentation
write-up that keeps writing about this attack from being reported as the attack.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party documentation -> `tests/corpus/clean/` | Verbatim text from external pages enters the repo as the only false-positive gate it has; a mis-sourced or softened line weakens the gate silently |

| write-up prose -> `MatchContext` downgrade | A specimen that is clean in both directions has stopped testing anything, and can be used to "fix" a false positive by widening the downgrade |
