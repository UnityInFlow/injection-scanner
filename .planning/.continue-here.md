## Critical anti-patterns — discovered through failure this session

| Pattern | How it manifested | Severity | Prevention |
|---|---|---|---|
| **Unit tests substituted for the sweep** | 16 green decoder unit tests while the release binary **panicked** on this repo — `tail[..12]` sliced mid-char on a `·` in ordinary source | blocking | Run `check .` with the release binary on every pass. Fixtures are not real bytes. |
| **A negative test with no positive control** | "silent on prose" passes equally if the regex simply fails to match | blocking | Every scope/suppression test ships a control asserting the same input *does* fire through the other path. |
| **Inheriting a documented reason without measuring it** | "the three misses are the base64 family" was wrong for 2 of 3, and propagated into REQUIREMENTS, STATE, README and a release note | blocking | Derive a phase's success criteria from measurement, never from the previous phase's prose. ## Next action

**Plan Phase 3 — CAT-01, issue #33.** `/gsd-plan-phase 3`

This is **the first phase that ships patterns**, which changes the risk profile completely:

- Phases 1 and 2 were provably behaviour-neutral (ENG-01: 728 findings identical to v0.1.0) or
  purely additive with zero losses (ENG-02: +12, −0). **Phase 3 carries real false-positive risk.**
- **GATE-01 applies for the first time**: 12 new corpus payloads in `tests/corpus/attack/`, written
  from the threat model and **never derived from the patterns** — a corpus built from each
  pattern's own `example` scores 100% by construction and measures nothing.
- **GATE-05 applies**: mutation-test the false-positive control. Two of four v0.1.0 widenings had a
  control the corpus was not actually holding.

`#33` splits in half: the **structured** half (`allowed-tools: *`, `Bash(*)`, `"tools": ["*"]`)
needs `scope: frontmatter`, which ENG-01 now provides; the **prose** half
(`--dangerously-skip-permissions`, "no need to ask", "add this to your settings.json") uses the
ordinary engine.

**Ask what the nearest legitimate document looks like before widening.** For this category it is a
CLAUDE.md or a settings reference — documents that legitimately *discuss* permissions. The
`instruction_injection` precedent (#97) is the warning: a CLAUDE.md is imperative and
model-addressed top to bottom, the same grammar as a payload, and the two differ by **provenance**,
which a regex cannot see.

## Standing gates

| Gate | Rule |
|---|---|
| GATE-01 | 12 threat-model corpus payloads per category, never derived from patterns |
| GATE-02 | Recall pinned **exactly** — an improvement fails the build too (it did, this session) |
| GATE-03 | Repo sweep on every pattern change; expect `[]` outside `examples/ patterns/ tests/ tools/` |
| GATE-04 | One category per PR |
| GATE-05 | Mutation-test the false-positive control |

Also standing: `main` stays strictly linear. A pattern's `name` is a **consumer contract** —
`pattern_name` ships in the JSON `spec-ci-plugin` reads, so widen the `description`, never rename.
