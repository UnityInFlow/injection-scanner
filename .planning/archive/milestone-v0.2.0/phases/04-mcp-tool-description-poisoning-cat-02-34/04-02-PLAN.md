<objective>
Land CAT-02's twelve threat-model payloads and the measured score they get from the pattern set that
exists today. **No `PI060`+ pattern exists at the end of this plan — that is the point.**

Purpose: GATE-01's only enforcement mechanism is ordering. A corpus written after the patterns, or
derived from their `example` values, scores well by construction and measures nothing. Writing the
payloads first and committing their pre-pattern score makes the later delta a readable diff in git
history rather than a claim in a PR description. This plan also discharges the one measurement plan
04-04's regex construction depends on: that the projection reaches a manifest's leaf keys regardless
of which wrapper key — or none — sits above them.

Output: twelve payloads across a prose file and a per-category structural subdirectory, a
wrapper-shape projection probe with a negative control, two exactly-pinned `EXPECTED` rows carrying
the measured baseline, and the README recall table widened to match.
</objective>

| Boundary | Description |
|----------|-------------|
| corpus payload -> `frontmatter::extract`/`parse` | Attacker-shaped JSON and YAML enters the bounded parser on the same path a real scan takes |

| README recall table -> consumers | The published number is the tool's central claim; a table that drifts from `EXPECTED` is a false claim in the repo's own voice |
