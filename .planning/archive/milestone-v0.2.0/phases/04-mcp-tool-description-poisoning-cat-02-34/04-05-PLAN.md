<objective>
Ship the arms this category is named for: instructions hidden in a tool's own `description`, read by
the model on every call and never surfaced in a UI. Three patterns, HIGH, prose-scoped, each
narrowed to D-01's discriminator from its first committed draft.

Purpose: the ROADMAP calls CAT-02 the highest false-positive risk in the milestone and
`04-RESEARCH.md` §Q3 measured exactly why. A bare second-person probe fires on the system-prompt
string in a clean-corpus specimen this repository already ships, and one widely deployed public MCP
server writes essentially every tool description in second-person obligation voice with almost the
same grammar as D-01's own fires-example. The discriminator that separates them is the OBJECT of the
instruction: the legitimate one directs the reader at the server's own declared protocol, the attack
directs it at a filesystem path, an environment variable, another tool's unrelated side effect, or
at concealing what it just did. That narrowing is not polish to add after a red corpus run — it is
the first draft.

Output: three HIGH prose patterns with mutation-tested controls anchored on real benign text, an
explicit record of what D-01 chooses not to see, and a two-directional GATE-03 delta.
</objective>

<decision_record>
**The description-poisoning arms are prose-scoped, not `scope: frontmatter`.** `04-PATTERNS.md` left
the arm assignment to discretion and sketched a structural option. Three measurements decided it.
First, `src/scanner.rs`'s decoded-layer pass skips any pattern whose scope is not prose, so a
frontmatter-scoped description arm cannot see an encoded payload — and an encoded payload inside tool
metadata is one of the four canonical shapes `04-RESEARCH.md` §Q4 documents. Second, the raw and
normalized passes already run over every line of a JSON manifest, so a prose arm reaches a poisoned
`description` in a `.mcp.json` anyway; scoping it structurally would add a second finding on the same
line without adding information. Third, a prose arm additionally reaches a poisoned description
quoted inside a markdown skill file or a fetched document, which is the delivery vector the tool's
README promises to cover and which a frontmatter-scoped arm cannot see at all.

The cost is that these findings carry ordinary confidence rather than the structural pass's 1.0 and
are subject to the code-fence downgrade. That is the correct trade for this category: a poisoned
description is a sentence, and the false-positive control is the discriminator rather than the
parser. The three config-hygiene arms in plan 04-04 remain frontmatter-scoped, because a package
runner invocation in a README install snippet is legitimate and only the projection can tell the two
apart.
</decision_record>
