# Cut v0.1.0, then bump the consumer's default

Closes #86. Follows `docs/RELEASE-CHECKLIST.md` rather than reading `release.yml` from scratch.

`main` is 56 commits past `v0.0.3` with 0 merge commits, CI and Code scanning both green,
`Cargo.toml` still reads `0.0.3`. The release is inert until `spec-ci-plugin`'s default moves,
so task 4 is part of the job, not a follow-up.

## Task 1 — Pre-tag gate (local)

**Files:** none
**Action:** run the four checks `release.yml`'s `test` job runs, in checklist order:
`cargo fmt --all -- --check`, `cargo clippy --all-targets --locked -- -D warnings`,
`cargo test --locked`, `cargo build --release --locked`.
**Verify:** all four exit 0.
**Done:** a red gate here stops the release; nothing is committed until it is green.

## Task 2 — Version bump + CHANGELOG

**Files:** `Cargo.toml`, `Cargo.lock`, `CHANGELOG.md`
**Action:**
- `version` 0.0.3 → 0.1.0; refresh `Cargo.lock` via a build so the lockfile records it.
- Promote `[Unreleased]` to `## [0.1.0] - 2026-08-29`. The existing section predates the
  detection rewrite — add the five merged PRs (#94/#80, #96/#95, #98/#97, #100/#99, #103/#102),
  the recall corpus (#81), the test gates (#29, #70) and the pattern catalogue.
- Add the `[0.1.0]` compare link; leave a fresh empty `[Unreleased]` above it.

**Verify:** `cargo metadata` reports 0.1.0; `Cargo.lock` shows it; CHANGELOG has both the new
heading and the compare link.
**Done:** one atomic commit. The tag guard in `release.yml` compares
`cargo metadata` against `${GITHUB_REF_NAME#v}` — a mismatch fails the release loudly.

## Task 3 — Tag, push, watch

**Files:** none
**Action:** annotated tag `v0.1.0` (v0.0.3 was annotated with a release body — match that shape),
push commit then tag. Watch the four jobs in dependency order: `test` → `build-binaries` →
`release` → `verify-published-assets`.
**Verify:** all four Linux legs green (the two `*-apple-darwin` legs are `continue-on-error`);
both musl URLs return 200 at the new tag.
**Done:** Release published with SHA256SUMS.txt and SLSA provenance.

## Task 4 — Bump the consumer (`04-spec-ci-plugin`)

**Files:** `src/injection-scanner.ts`, `action.yml`, `README.md`
**Action:** `DEFAULT_SCANNER_VERSION` and the two restatements v0.0.3 → v0.1.0. A test pins all
three together because they had silently drifted before. **Do not** touch the two *historical*
references (`src/injection-scanner.ts:23` "v0.0.3 is the first release where…", `README.md:123`
"added in `v0.0.3`") — those are statements about the past and stay true.
**Verify:** `npm test` green; `assertSupportedVersion("v0.1.0")` passes (min is v0.0.2).
**Done:** committed on a branch in that repo — separate repo, separate PR.

## Constraints carried in

- **Never a merge commit.** `main` has 0 since v0.0.3; keep it that way.
- **The musl asset names are a public API** of this repo — raw, unextensioned, target-triple-named.
- **A bad release is fixed by a new tag**, never by moving or deleting a published one.
- `release.yml` runs on `ubuntu-latest` deliberately (#45) — do not "restore" a self-hosted label.
